# AI 分类响应容错设计

## 背景

2026-08-06 的定时任务把 6 条候选新闻全部记录为「已分析且不匹配」，但使用相同新闻再次诊断时，模型正确识别出 2 条相关内容，得分均为 0.78。最低分数阈值不是本次漏报原因。

当前分类流程存在两个问题：

- 分类请求沿用全局 `temperature=1.0`，同一批输入可能产生明显不同的判断。
- 空响应、无法提取 JSON 和 JSON 语法错误都被解析为 `[]`，与模型明确返回的合法空数组无法区分。流水线随后把整批新闻记录为「已分析且不匹配」，后续运行不会重试。

## 目标

- 降低相同新闻重复分类时的随机波动。
- 区分「合法无匹配」与「分类响应无效」。
- 对可修复的 JSON 格式错误自动重试一次。
- 无法可靠解析时不写入已分析状态，允许后续任务重试。
- 保持现有标签规则、相关度阈值和推送排序不变。

## 方案

### 分类请求

首次分类固定使用 `temperature=0`。全局温度仍供摘要、翻译等其他功能使用，不在本次修改范围内。

### 响应判定

分类解析返回以下三种语义：

- 合法的非空 JSON 数组：正常解析并保存匹配结果。
- 合法的空数组 `[]`：表示模型明确判定本批没有匹配新闻，允许记录为已分析。
- 空响应、无法提取 JSON、顶层不是数组或 JSON 语法错误：表示分类失败，不得视为无匹配。

### 修复重试

首次响应无效时，保留原始对话并追加固定修复指令，要求模型仅返回严格 JSON 数组。修复请求使用 `temperature=0`，最多执行 1 次。

如果修复响应仍无效，`classify_batch()` 返回失败状态。流水线沿用现有失败批次逻辑，不保存匹配结果，也不把本批新闻写入已分析表。

### 日志

正常模式下记录首次解析失败类型、是否进入修复重试，以及最终是否保留待重试。日志不得输出 API Key，也不默认输出完整新闻正文或完整模型响应。

## 数据流

1. 使用温度 0 请求批量分类。
2. 解析并验证响应顶层结构。
3. 合法数组进入现有字段校验与标签 ID 校验。
4. 无效响应触发一次低温 JSON 修复请求。
5. 修复成功后正常保存；修复失败则返回批次失败。
6. 只有成功解析的响应才会更新已分析状态。

## 测试

至少覆盖以下情况：

- 首次返回合法非空数组，正常得到分类结果，并确认温度为 0。
- 首次返回合法 `[]`，返回成功的空结果，不触发重试。
- 首次返回空字符串，修复重试后成功。
- 首次返回损坏 JSON，修复重试后成功。
- 两次响应均无效，返回失败状态。
- 两次均无效时，流水线不记录本批新闻的已分析状态。
- 原有完整测试集保持通过。

## 部署与数据修复

代码验证通过后重建 Docker 容器。清除 2026-08-06 数据库中本次错误写入的 6 条未匹配分析状态，再立即运行一次任务；已抓取新闻数据和其他日期数据库不删除。
