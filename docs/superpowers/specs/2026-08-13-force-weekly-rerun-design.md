# `--force-weekly` 人工重跑设计

## 目标

`--force-weekly` 无论在哪一天执行，都重新在线采集上一个完整自然周发布的候选，重新生成 PDF，并再次向所有已配置企业微信账号发送。人工重跑不应要求重建容器，也不应被已有 analyze、逐账号投递或全局 push 检查点短路。

正常定时运行保持现有幂等语义：同一自然周成功后跳过；部分账号失败时只续投失败账号。

## 行为边界

- 内容窗口仍为 `上周一 00:00 <= published_at < 本周一 00:00`。
- 人工强制运行仍使用周锁，避免同周任务并发发送。
- 人工强制运行忽略已有 analyze、逐账号 PDF 投递和全局 push 检查点，但不删除历史账本。
- 人工强制运行重新抓取并重建权威周快照、三模块 PDF；分类阶段可复用当前提示词契约下仍有效的 AI 缓存。
- 人工强制发送本次 PDF 给所有当前账号，不使用逐账号续投账本；完成后仍记录全局周期成功状态。
- 自动重试不得使用 `--force-weekly`，否则会重复发送；其继续使用普通周报幂等/续投逻辑。

## 实现方式

1. 在周报主流程中识别人工强制运行，跳过全局 push 的提前返回和 partial-resume。
2. 在 AI 分析入口忽略既有 analyze 检查点，重新生成本次周报叙事。
3. 在 PDF 投递入口忽略已有全局及逐账号账本，直接向所有账号发送。
4. 清理宿主机 `daily.crontab` 中自动重试命令的 `--force-weekly`。
5. 更新 CLI 帮助文案，并用回归测试同时锁定人工强制和自动幂等两条路径。
