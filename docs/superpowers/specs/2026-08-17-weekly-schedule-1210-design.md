# 周报定时调整设计

## 目标

将每周一周报的首次自动运行时间改为北京时间 `12:10`；若本周期尚未成功，则在 `12:30`、`13:00`、`13:30` 自动重试。周二至周日仍在 `10:00` 静默采集。

## 设计

- Docker 默认 Cron、`docker/.env` 与 `docker/.env.example` 使用同一组表达式：`0 10 * * 0,2-6;10,30 12 * * 1;0,30 13 * * 1`。其中 `0,2-6` 是 supercronic 兼容的“周日及周二至周六”。
- 周一不再执行每日 `10:00` 触发；`12:10` 是首次正式运行，后续三个时刻只是失败重试触发。已有全局成功检查点时，后续触发必须在采集、分析、PDF 生成和外部推送前短路。
- 中英文时间线中的 `monday_weekly` 有效窗口同步改为 `[12:10, 13:31)`，确保四次触发均进入周报模式，其他时刻不会误运行周报。
- `config/daily.crontab` 与项目交接文档、README、技术说明同步更新，避免部署入口之间再次产生时间差异。
- 不改变上一自然周的内容范围、静默采集逻辑、幂等检查点或 PDF 投递逻辑。

## 验证

- 配置测试精确断言中英文周一窗口及四个触发时刻。
- 可移植部署测试精确断言默认 Cron、示例环境变量和 crontab 活动项。
- 运行相关 Python 配置测试、Shell 部署测试和 `git diff --check`。
