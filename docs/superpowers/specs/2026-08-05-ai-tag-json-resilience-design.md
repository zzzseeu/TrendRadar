# AI 标签 JSON 解析容错设计

## 背景

AI 标签提取偶发返回字符串内含未转义换行或制表符的 JSON。当前实现直接调用严格模式 `json.loads()`，解析失败后返回空标签，整条 AI 筛选流水线随即退回关键词匹配，导致有效新闻被漏筛。

## 方案比较

1. 仅要求模型输出严格 JSON：改动最小，但提示词无法保证模型始终遵守格式。
2. 仅使用 `response_format`：约束最强，但当前自定义网关和模型是否完整支持该参数尚未验证。
3. 低温调用配合定向容错与一次重试：不依赖网关扩展能力，可以覆盖本次故障，同时保留严格校验。

采用方案 3。

## 设计

- 标签提取调用固定使用 `temperature=0`，不改变新闻摘要等叙述性任务的全局温度。
- 先按严格 JSON 解析；仅当错误为 `Invalid control character` 时，使用 `strict=False` 再解析一次。
- 兼容解析后仍执行现有 `tags`、`tag`、`description` 结构校验，不放宽业务数据格式。
- 首次响应无法解析时，再请求模型一次；重试提示明确要求修正为单个 JSON 对象，且重试仍使用低温。
- 第二次仍失败时保持现有失败语义，由上层回退关键词匹配，不伪造标签。
- 日志记录解析失败和重试结果，但不打印完整兴趣内容或 API Key。

## 测试

- 合法 JSON 仍按原逻辑解析。
- 字符串内含未转义换行或制表符时可恢复并保留文本。
- 标签提取调用使用 `temperature=0`。
- 第一次响应无法恢复时会重试一次，第二次合法则成功。
- 连续两次不可恢复时返回空标签，调用次数恰为 2。
- 运行完整测试，确认新闻分类、AI 摘要和通知流程不受影响。

## 非目标

- 不改变兴趣标签内容、新闻准入条件或最低分数。
- 不降低全局 AI 温度。
- 不启用尚未确认兼容性的 `response_format`。
- 不处理任意残缺 JSON；括号缺失、字段截断等错误仍交给一次模型重试修复。
