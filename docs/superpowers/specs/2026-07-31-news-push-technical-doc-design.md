# 新闻推送技术文档设计

## 目标

编写一份用于项目汇报和成果展示的简短技术文档，重点说明现有新闻监控配置如何完成新闻采集、内容总结和企业微信推送，以及后续如何增加监控网站。

文档不重复介绍 TrendRadar，不展开完整运维手册或逐文件代码解析。

## 输出

- 文件：`docs/news-push-technical-implementation.md`
- 篇幅：约 1～2 页
- 语言：简洁中文
- 表达方式：1 张 Mermaid 流程图、必要的配置示例和少量文件路径

## 内容结构

1. **推送流程**
   - 定时任务触发。
   - RSS、新闻网页或 JSON 接口采集。
   - AI 筛选、总结和重点排序。
   - 生成 HTML 报告并发送企业微信消息。

2. **内容总结**
   - 按正文、摘要、标题的顺序选择证据。
   - 原文不可访问时自动降级并保留风险提示。
   - AI 根据关注方向筛选新闻，生成逐条摘要并进行二次证据校审。
   - 推送简短摘要、前 5 条重点新闻和原文链接。

3. **关键配置**
   - 调度时间、AI 模型和企业微信机器人参数分别由 Docker 环境变量和配置文件管理。
   - 文档只列参数名，不展示任何真实 API Key、Webhook、代理地址或其他敏感值。

4. **增加监控网站**
   - 有 RSS：在 `config/config.yaml` 的 `rss.feeds` 增加配置。
   - 无 RSS：配置 `source_type: web_news`，并在网页解析模块中增加来源规则。
   - 特殊 JSON 接口：增加独立解析函数，并在 RSS 抓取器中增加对应分支。
   - 每种方式只提供一个短示例和涉及的主要文件。

## 准确性要求

- 只描述当前代码中已经存在的行为。
- 明确区分 RSS 配置扩展与需要开发解析器的网站。
- 不承诺能够绕过反爬、登录、订阅或版权限制。
- 不删除或改写项目现有文档。

## 验收标准

- 文档脱离工具介绍也能独立说明推送技术链路。
- 读者可以理解新闻如何被采集、筛选、总结并发送。
- 维护者能够判断新增网站应采用配置方式还是代码扩展方式。
- 全文保持精简，不扩展为部署或故障排查手册。
