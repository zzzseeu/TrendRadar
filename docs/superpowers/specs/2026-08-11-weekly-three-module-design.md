# 每周 PDF 三模块与统一相关性标准设计

## 目标

将每周农业育种 PDF 固定拆分为三个一级模块：农业育种政策、农业育种科研文献、农业气象周报。政策与科研分别独立排序、各取最多 20 条；农业气象不参与新闻评分且不占新闻名额。全项目只保留一条 AI 相关性准入标准：`relevance_score >= 0.5`。

## 范围与约束

- 沿用北京时间上一自然周 `[周一 00:00, 下周一 00:00)` 作为唯一周报内容窗口。
- 沿用每日静默采集、周一生成、失败重试、跨进程周锁和逐账号 PDF 投递账本。
- 沿用一个 PDF、企业微信文件消息的投递形式，不恢复文字预览或文字回退。
- 政策与科研均不为数量而降分或补齐；任一模块可以合法为空。
- 同一新闻最多展示一次，归属政策时不得再次出现在科研模块。
- 不新增独立政府网页爬虫；政策召回复用现有 RSS 与新闻搜索主线，并扩展政策检索主题。
- 官方农业气象周报继续使用现有严格抓取和周期校验，不参与 AI 新闻分类。

## 候选数据流

1. 每日静默采集把固定 RSS 和新闻搜索结果写入日库，并持久化来源成功/失败状态。
2. 周一由 `WeeklyRSSAggregator` 严格读取上一自然周及运行日快照，按 `published_at` 过滤和规范化身份去重。
3. 同一周快照作为 AI 分类的唯一候选集合；抓取缺日、来源失败、存储损坏时继续严格失败。
4. AI 为每条候选输出一级模块、主题标签、相关性、重要性、摘要及证据字段。
5. 先应用全局唯一准入线 `relevance_score >= 0.5`，再按模块排序和截断。
6. 政策 TOP20、科研 TOP20 和官方农业气象共同渲染为一个 PDF。
7. 企业微信只发送该 PDF；发送成功后写入 PDF 摘要与账号哈希组成的投递记录，全部账号成功后写全局周检查点。

## 一级模块分类契约

AI 每条输入必须返回 `module_type`，值只能是：

- `policy`：农业育种政策。
- `research`：农业育种科研文献与实质科研/技术进展。
- `exclude`：与农业育种无关、重复、无法识别主题或内容无效。

### 农业育种政策

采用广义政策口径，包括：

- 种业振兴、种质资源保护及农业科研政策。
- 品种审定、品种登记、植物新品种权、种子法与种业监管。
- 转基因、基因编辑和生物育种产业化监管。
- 农业育种科研项目、财政支持和补贴政策。
- 政策部署、工作会议、领导调研、行业倡议和实施进展。
- 与上述事项直接相关的企业合作、产业项目和政策响应。

### 农业育种科研文献

包括：

- 同行评议论文、预印本、科研机构成果和重要数据资源。
- 基因、QTL、种质资源、遗传机制、育种材料和品种研发。
- 基因组、泛基因组、多组学、基因编辑、表型和智能育种模型。
- 企业发布的实质育种技术、研究平台、研发成果和新品种进展。
- 学术会议或产业活动中首次公开的可核验科研成果。

### 不再硬排除的内容

企业宣传、会议动态、领导调研、行业倡议和泛化宣传不再因表达形式被直接排除。它们进入正常 AI 判断：核心为政策部署时归入 `policy`，核心为科研或育种技术时归入 `research`；达到 `0.5` 才能进入候选。只有无关、重复、无法分类或内容无效时使用 `exclude`。

### 政策优先

同一新闻同时具备政策和科研属性时，一级模块必须选择 `policy`。模块选择完成后先按规范 URL、GUID 或规范标题全局去重；科研候选必须排除政策模块已经占用的身份。

## AI 输出与严格校验

分类响应中每条记录包含：

- `id`
- `module_type`
- `tag_id`（`policy` 和 `research` 必填）
- `score`
- `importance_score`
- `summary`
- 既有内容层级、风险及证据字段

`exclude` 记录允许不带 `tag_id`，只用于确认该输入已经由本次 Prompt 明确处理，不写入活跃结果。`policy` 或 `research` 缺少标签、分类未知、分数非有限数值、分数越界、ID 重复、输入 ID 遗漏或出现未知 ID时，严格周报整批失败，不能默认落入科研模块。

分类 Prompt 的哈希变化使旧分类失效。旧结果没有合法 `module_type` 时不得复用，必须重新分类。

## 兴趣文件与 Prompt

### `config/ai_interests.txt`

- 扩展农业政策与种业监管为本规格的广义政策范围。
- 删除对企业宣传、会议、领导调研和营销表达的硬排除。
- 明确政策优先、科研次之、同一新闻只进入一个模块。
- 保留原有 20 个细分兴趣方向，作为模块内部主题标签。

### `config/ai_filter/prompt.txt`

- 把一级模块作为必填分类维度。
- 每个输入 ID 都必须返回一条 `policy`、`research` 或 `exclude` 记录。
- 明确政策/科研边界、政策优先及无关内容排除条件。
- 保留 `score`、`importance_score` 和摘要的严格标量要求。

### `extract_prompt.txt` 与 `update_tags_prompt.txt`

- 删除“会议宣传、营销不得形成标签”的绝对约束。
- 标签仍负责模块内部主题组织，不替代一级模块。
- 标签总数和结构化 JSON 契约保持现有严格要求。

### `config/ai_analysis_prompt.txt`

- 周报叙事分别总结政策趋势、科研进展和气象风险。
- 不把三类内容混写为一个无法追溯来源的泛化结论。

## 全局唯一相关性阈值

- 中文和英文配置中的 `ai_filter.min_score` 均改为 `0.5`。
- 所有模式都读取同一个 `MIN_SCORE`，不增加 weekly 专用覆盖值。
- 删除代码、测试和文档中对生产默认值 `0.7` 的旧假设。
- `0.5` 是准入线，不是排名分；低于该值的 `policy` 和 `research` 结果均不进入报告。

## 两个 TOP20 的排序

政策和科研分别独立排序，排序键依次为：

1. `importance_score` 降序。
2. `relevance_score` 降序。
3. 证据完整度：全文高于摘要，摘要高于仅标题。
4. 发布时间降序。
5. 来源名、标题和稳定身份，保证相同输入产生确定顺序。

每个模块去重后截取前 20 条。政策和科研各自前 5 条仅增加“重点政策”或“重点文献”标记，不在其他区域重复渲染。

## PDF 结构

PDF 固定按以下顺序渲染：

1. 封面和分模块核心观点。
2. 农业育种政策，最多 20 条；为空时显示“本周暂无符合条件的政策新闻”。
3. 农业育种科研文献，最多 20 条；为空时显示“本周暂无符合条件的科研文献”。
4. 农业气象周报，展示气象影响、未来展望、区域/作物风险和生产建议。
5. 趋势与指标，分别显示政策数、科研数、模块主题覆盖和气象状态。
6. 数据与方法说明。

每张新闻卡显示模块内排名、重点标记、主题、发布时间、来源、AI 摘要和安全原文链接。删除现有全局“重点新闻”和“入选新闻”的重复展示。分页继续使用原生页眉/页脚，长气象正文允许跨页。

## 存储与重试

- 为持久化 AI 结果增加 `module_type`，值限制为 `policy` 或 `research`。
- SQLite 旧库采用幂等迁移；旧行的空模块值只能触发重新分类，不能静默默认。
- 本地和远程严格结果读写、批次事务、回滚和 CAS 契约必须覆盖新字段。
- 周报 PDF 路径仍由自然周决定；同一份 PDF 摘要用于逐账号成功账本。
- 分类、写入、渲染或发送任一步失败时，不推进全局周检查点；部分账号成功时继续使用现有逐账号账本重试。

## 旧缓存与结果清理

清理必须发生在新代码测试通过且新三模块 PDF 已成功生成、验证和投递之后，不能先删再试：

- 删除旧版周报 PDF、对应 HTML、临时渲染图片、文字坐标文件和回滚副本。
- 删除或失效缺少合法 `module_type`、使用旧 Prompt 哈希或旧 `0.7` 门槛的 AI 分类与活跃结果；当前周期由新 Prompt 重新分类。
- 同一自然周最终只保留一套正式三模块 HTML/PDF，不保留旧布局或旧摘要文件。
- 清理 `docs/superpowers` 中被新规格和实现计划替代的旧文档，只保留本次最新规格与计划。
- 保留原始 RSS 日库、来源成功/失败状态、first-seen/outbox、严格存储 provenance、调度检查点和逐账号投递记录。它们是权威采集与审计状态，不是冗余缓存；删除会破坏自然周完整性、失败重试或防重复发送。
- 清理前精确列出目标，清理后验证正式文件摘要、数据库新模块结果、企业微信投递账本和工作树状态。

## 错误处理

- 政策为 0 条、科研为 0 条均为合法，不降低门槛补齐。
- 两类同时为空但气象有效时，允许生成仅气象 PDF。
- 两类同时为空且气象缺失时，严格失败。
- AI 响应不完整、Prompt 契约损坏、结果存储失败、周历史来源不完整或气象周期不匹配时，严格失败且不推送。
- 普通模式共享 `0.5` 阈值，但继续保留各自既有的失败传播语义。

## 验证标准

- 单元测试证明广义政策、科研和 `exclude` 的分类边界。
- 单元测试证明政策优先、跨模块不重复、模块各自最多 20 条及确定排序。
- 配置和静态扫描证明生产阈值只有 `0.5`，不存在 weekly 特例和旧 `0.7` 默认。
- 存储测试证明 `module_type` 本地/远程写入、读回、迁移、批次回滚和失败关闭。
- Prompt 测试证明每个输入 ID 都有结果，未知分类和结构错误被拒绝。
- PDF 测试证明三个一级模块、空模块文案、两个独立 TOP5 标记、最多 40 条且无重复。
- 真实 Chromium 测试验证 A4、多页、中文提取、页眉页脚和长内容分页。
- 企业微信测试证明只发送一个 PDF，不发送文字消息，逐账号账本与失败重试保持有效。
- 清理验收证明旧版 PDF/HTML、临时渲染文件及旧 AI 分类缓存不存在，正式目录只保留最新三模块结果。
- 回归覆盖普通模式、每日静默采集、自然周聚合、官方气象、调度锁、PDF 投递和现有存储一致性。

## 验收结果

一次成功周报应当满足：PDF 只有三个一级内容模块；政策和科研分别不超过 20 条、互不重复且均达到 `0.5`；气象来自本交付周期的官方周报；企业微信仅收到一个 PDF；成功账号与全局周检查点均有可验证记录。
